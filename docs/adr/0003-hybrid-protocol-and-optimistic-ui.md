# 0003 - 混合同步协议与前端乐观表现边界

实时对局协议有两种流派：纯事件流（前端累积状态，丢一次包就永久分叉、重连难做）与全量状态同步（每步发整个棋盘，冗余且动画语义差）。决定采用混合同步：回合开始与重连时下发全量快照（棋盘、分数、剩余时间、当前操作方），回合内下发增量事件（交换结果帧：消除集合、下落移动、补充棋子、本次得分、归属方）；前端零计算、纯重放动画。协议为 JSON over WebSocket，消息带版本字段，未来可平滑替换编解码层为二进制。

服务端没有动画时间概念——一次交换在其事件循环内瞬时完成全部结算（消除、下落、连锁、计分），动画纯属前端对结果帧的重放。同一玩家在前一交换动画未播完时即可发起下一次交换，服务端按到达顺序串行判定。

## 前端乐观表现的边界

10 秒竞速窗口叠加网络 RTT，若每次交换都等服务器确认才播动画会明显卡顿。因此允许前端做**无状态乐观表现**：交换后立即播放交换动画，收到服务端结果帧后继续（有效）或立即回弹（无效）。这不是写路径的例外——本地预测不写入任何权威状态，一切以服务端结果帧为准，冲突时无条件回滚。ADR-0001 的"零写路径"指状态权威，不禁止表现层预测。

## Consequences

- 重连 = 拉一次快照，协议上零额外成本。
- 丢包与状态分叉由回合边界快照天然对账。
- 前端需要一个"预测中"的中间表现态和收到否决后的回弹动画路径，这是表现层的主要复杂度。
