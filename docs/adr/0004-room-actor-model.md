# 0004 - 单房间单 goroutine 事件循环（房间 Actor 模型）

对局房间是天然串行的世界：回合因果链（交换 → 消除 → 连锁 → 落定 → 计分 → 回合流转）必须按顺序结算，10 秒窗口计时与玩家操作随时并发到达。若用共享状态加锁，"计时到期"与"交换请求"同时到达即是经典竞态，锁的粒度设计会成为长期 bug 之源。因此决定：每个房间一个事件循环 goroutine，所有输入——两名玩家的 WS 消息、回合定时器、掉线宽限定时器、排队超时——统一汇入该房间的 channel 串行处理；房间状态仅此 goroutine 可写；判定器（连线检测、L/T 合并、重力下落、连锁结算、计分、死局检测、初始棋盘生成）实现为无副作用纯函数。

## Considered Options

- **共享状态 + sync.Mutex**：实现直观，但回合制的定时器/操作竞态无法靠锁纪律根除。否决。
- **每玩家每消息临时加锁处理**：锁粒度更碎，竞态面更大。否决。

## Consequences

- 房间间完全并发（天然按房间分片水平扩展），房间内绝对串行（无竞态可能）。
- 玩家 WS 连接的读写 pump 跑在独立 goroutine，与房间之间只通过 channel 通信；房间向慢消费者发送的阻塞/丢弃策略在实施时定。
- 判定器为纯函数，可全量 table-driven 单测；房间层只需测状态机流转。
- "服务端全权判定"（ADR-0001）由此获得工程兑现：判定逻辑不在并发泥潭里，审计路径唯一。
